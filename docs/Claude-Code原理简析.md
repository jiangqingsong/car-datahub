# Claude Code 原理简析

> 从小白视角理解 Claude Code 是怎么工作的，以及如何更高效地使用它。

---

## 一、一句话概括

Claude Code 是一个**以大模型为核心的命令行编程助手**。你把代码仓库交给它，用自然语言告诉它要做什么，它自己去读文件、写代码、跑命令，反复迭代直到完成任务。

---

## 二、核心工作流：Agent Loop（代理循环）

这是理解 Claude Code 最重要的概念。它每次工作的流程是一个循环：

```
你发出指令 → AI 思考 → AI 调用工具 → 工具返回结果 → AI 再思考 → 再调用工具 → ... → 任务完成
```

举个例子，你说"帮我把用户表加一个 phone 字段"：

| 轮次 | AI 做什么 | 用什么工具 |
|------|-----------|-----------|
| 1 | 搜索项目中哪里定义了用户表 | Grep（代码搜索） |
| 2 | 读到表结构代码 | Read（读文件） |
| 3 | 修改文件加上新字段 | Edit（编辑文件） |
| 4 | 运行测试验证 | Bash（执行命令） |

每一步 AI 都根据上一步的结果决定下一步做什么。这就是 **Agent Loop**——循环执行"思考 → 行动 → 观察"直到目标达成。

**关键认知**：你不是在和一个聊天机器人对话，你是在指挥一个能操作你电脑的 AI 代理干活。

---

## 三、两个重要概念

### 3.1 上下文窗口（Context Window）

AI 能"记住"的对话内容是有限的，这个限制叫上下文窗口。可以理解为 AI 有一个固定大小的"工作记忆"。

- 对话太长时，早期内容会被**压缩摘要**（compaction），不是直接丢弃
- 所以要**一次说清楚一个任务**，避免在同一个会话里来回跳跃多个不相关的话题
- 大文件读取后也会占用上下文，AI 会尽量只读必要的部分

### 3.2 系统提示（System Prompt）

每次对话开始时，AI 会收到一份"工作说明书"，定义了：
- 它是谁、能做什么
- 有哪些工具可以用
- 行为准则（比如：先想再动手、不要随意提交代码、安全第一）
- 当前项目的基本信息（git 状态、分支名等）

这份说明书你一般看不到，但它决定了 AI 的基础行为模式。

## 四、Claude Code 有哪些"超能力"？

### 4.1 工具集

AI 通过调用工具来和你的电脑交互：

| 工具 | 干什么 |
|------|--------|
| **Read** | 读文件内容 |
| **Write** | 创建/覆盖文件 |
| **Edit** | 精确替换文件中的某段代码 |
| **Grep** | 在代码中搜索关键字/正则 |
| **Glob** | 按文件名模式查找文件 |
| **Bash** | 执行终端命令（git、npm、测试等） |
| **Agent** | 派一个子代理去独立完成子任务 |
| **WebSearch / WebFetch** | 搜索网络 / 获取网页内容 |

### 4.2 技能系统（Skills）

Skills 是告诉 AI"在什么场景下、按什么流程干活"的规则文件。你刚体验的 brainstorming 就是一个 Skill：

- **触发条件**：你要做新功能、加组件、改行为
- **规定流程**：先问需求 → 提方案 → 画设计 → 写文档 → 确认后再动手
- **铁律**：哪怕需求简单，也必须走完流程

常见的 Skill 还有：
- `test-driven-development`：先写测试再写代码
- `systematic-debugging`：遇到 bug 先排查根因再修
- `writing-plans`：把设计拆成可执行步骤
- `verification-before-completion`：做完后必须验证通过才算完

**Skill 可以自动触发**——当你说"帮我加一个导出功能"，AI 会自动判断"这是需要 design 的场景"，然后按 brainstorming 流程走。

### 4.3 子代理（Sub-Agent）

遇到复杂任务时，AI 可以"分身"：派一个子代理去独立完成某个子任务（比如搜索整个代码库找一个函数的全部引用），子代理完成后汇报结果，主会话继续。这样做的好处是：
- 大规模搜索不会撑爆主会话的上下文
- 多个独立子任务可以并行执行

## 五、Claude Code 能"记住"什么？

### 5.1 会话内（本次对话）
- 对话历史（会被压缩但主题会保留）
- 已读取的文件内容
- 执行的命令输出

### 5.2 跨会话（持久记忆）

Claude Code 有多层记忆机制：

| 层级 | 位置 | 作用 | 示例 |
|------|------|------|------|
| **CLAUDE.md** | 项目根目录 | 项目级的 AI 行为指南 | "这个项目用 Python 3.12，测试用 pytest" |
| **Memory** | `~/.claude/projects/<项目>/memory/` | AI 自动记录的关于你/项目的持久记忆 | 你的角色偏好、这个项目的背景 |
| **Settings** | `.claude/settings.json` | 权限、环境变量等配置 | 允许哪些命令自动执行 |
| **Skills** | `.claude/skills/` 或全局安装 | 团队共享的工作流规则 | 代码审查流程、部署规范 |

**实用建议**：在项目根目录放一个 `CLAUDE.md`，写清楚：
- 项目是干什么的
- 用的什么技术栈
- 有什么特殊约定（命名规范、目录结构等）

系统提示中会告知 AI 关注这个文件，但 AI 是否真的去读取取决于具体行为——这也是为什么有时候你发现 AI 并没有遵循 CLAUDE.md 里的指令。建议在对话开始时明确提醒 AI 读取它，或者在 CLAUDE.md 中用简洁、醒目的写法提高被注意的概率。

## 六、权限模型：AI 什么时候需要你批准？

Claude Code 有分级权限控制：

- **读操作**（Read、Grep、Glob）：通常自动放行
- **编辑文件**（Edit、Write）：在项目范围内自动放行
- **执行命令**（Bash）：取决于你的权限设置
- **网络请求**（WebFetch、WebSearch）：通常需要批准
- **危险操作**（rm -rf、force push、删除数据库）：AI 会主动向你确认

你可以在 `.claude/settings.json` 里配置哪些操作可以跳过确认。

## 七、高效使用要点

### 做：
- **一次说清楚一个任务**，给足上下文（为什么要做、约束条件是什么）
- **在项目根目录放 CLAUDE.md**，写清项目约定
- **信任流程**：AI 的 design → plan → implement → verify 流程是经过验证的
- **把 AI 当结对编程的同事**：它擅长理解需求、写代码、排查问题，但不擅长猜你心思

### 不做：
- 不要在同一个会话里来回跳跃多个不相关的任务——上下文会被搞乱
- 不要让 AI 做它无法验证的事情（比如"把这个项目部署到生产环境"——它看不到生产环境）
- 不要跳过设计直接写复杂功能——返工成本远高于多花 5 分钟做 brainstorming

### 一个小技巧：
在对话中用 `!` 前缀可以让你直接在终端执行命令并把输出注入对话。比如：
```
! git log --oneline -5
```
这比让 AI 帮你跑 git 命令更快。

## 八、总结

```
你（人类）                      Claude Code（AI 代理）
  │                                    │
  │   "帮我做 X"                        │
  │ ──────────────────────────────────→ │
  │                                    │  读 CLAUDE.md + 项目结构
  │                                    │  判断是否需要设计讨论
  │                                    │  执行 Agent Loop：
  │                                    │    搜索 → 阅读 → 编辑 → 测试
  │                                    │  直到完成
  │   "完成，改动如下..."               │
  │ ←────────────────────────────────── │
  │                                    │
  │   你审查改动，提出修改               │
  │ ──────────────────────────────────→ │
  │                                    │  继续 Agent Loop...
```

**核心认知**：Claude Code 不只是一个聊天窗口，它是一个能操作文件系统、执行命令、管理 Git 的**编程代理**。你负责拍板（做什么、做到什么程度算好），它负责执行（查代码、写代码、跑测试）。
