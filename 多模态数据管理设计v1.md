# 多模态数据管理设计 v1

## 数据流回顾

```
云端下发采集任务 → 车端采集 → 上传到云端
  ├─ BLF（CAN 原始信号）→ DBC 解析 → StarRocks（结构化）
  └─ MCAP（视频/点云）→ S3 直接存储（非结构化）
       │
       ├─ CAN 数据：时间对齐 → 场景切片
       ├─ MCAP 数据：时间段切片 → 采样输出图片 → 标注平台
       └─ CAN + MCAP 统一时间切片 → 融合分析
```

## 一、S3 目录组织规范

```
s3://xeos-bucket/
│
├── raw/                                    # 原始数据层
│   └── {vehicle_id}/                       # 按车辆分区
│       └── {date=%Y%m%d}/                  # 按天分区
│           └── {task_id}/                  # 按采集任务分区
│               ├── blf/                    # CAN 原始信号
│               │   └── {file_id}.blf
│               └── mcap/                   # 视频/点云
│                   └── {file_id}.mcap
│
├── parsed/                                 # 解析后数据
│   └── can/                                # CAN 解析结果
│       └── {vehicle_id}/
│           └── {date=%Y%m%d}/
│               └── {blf_file_id}/
│                   ├── signals.parquet      # 解析后的信号值（归档，热数据在 StarRocks）
│                   └── _manifest.json       # 解析元信息（DBC 版本、信号列表、时间范围等）
│
├── slices/                                 # 切片数据
│   └── {slice_id}/                         # 每个切片一个目录
│       ├── _slice_meta.json                # 切片元信息
│       ├── can/
│       │   └── signals.parquet             # 该时间窗口的 CAN 信号
│       ├── mcap_video/
│       │   └── frames/                     # 视频帧采样
│       │       ├── %06d.jpg
│       │       └── _frame_index.json       # 帧号 → 时间戳映射
│       └── mcap_lidar/
│           └── points/                     # 点云帧采样
│               ├── %06d.pcd
│               └── _frame_index.json
│
└── fusion/                                 # 融合分析结果
    └── {fusion_id}/
        ├── _fusion_meta.json               # 融合参数、对齐策略
        └── aligned/                        # 对齐后的各模态数据
            ├── can/
            ├── video/
            └── lidar/
```

## 二、核心元数据表 DDL（PostgreSQL）

### 1. 采集任务

```sql
CREATE TABLE collection_tasks (
    task_id          VARCHAR(64)   PRIMARY KEY,
    task_name        VARCHAR(256)  NOT NULL,
    vehicle_id       VARCHAR(64)   NOT NULL,
    status           VARCHAR(32)   NOT NULL DEFAULT 'pending',  -- pending/collecting/uploaded/completed/failed
    config           JSONB         DEFAULT '{}',                -- 采集配置（采样率、传感器、时长等）
    dbc_version      VARCHAR(64),                               -- 关联的 DBC 版本号
    scheduled_start  TIMESTAMP,
    scheduled_end    TIMESTAMP,
    created_at       TIMESTAMP     NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMP     NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE collection_tasks IS '云端下发的采集任务定义';
```

### 2. 采集会话（一次任务可能多次上传）

```sql
CREATE TABLE collection_sessions (
    session_id       VARCHAR(64)   PRIMARY KEY,
    task_id          VARCHAR(64)   NOT NULL REFERENCES collection_tasks(task_id),
    vehicle_id       VARCHAR(64)   NOT NULL,
    vin              VARCHAR(32),                                 -- 车架号
    start_time       TIMESTAMP     NOT NULL,
    end_time         TIMESTAMP,                                   -- 可为空（上传未完成时）
    duration_sec     INTEGER,                                     -- 采集时长（秒）
    can_bus_ids      TEXT[] DEFAULT '{}',                         -- 采集的 CAN 总线 ID 列表
    data_size_bytes  BIGINT        DEFAULT 0,                     -- 原始数据总大小
    status           VARCHAR(32)   NOT NULL DEFAULT 'uploading',  -- uploading/uploaded/parsing/parsed/completed/failed
    uploaded_at      TIMESTAMP     DEFAULT NOW(),
    created_at       TIMESTAMP     NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE collection_sessions IS '一次采集会话 = 车辆执行一次采集任务后上传到云端的记录';
```

### 3. 原始数据文件

```sql
CREATE TABLE data_files (
    file_id          VARCHAR(64)   PRIMARY KEY,
    session_id       VARCHAR(64)   NOT NULL REFERENCES collection_sessions(session_id),
    task_id          VARCHAR(64)   NOT NULL,
    vehicle_id       VARCHAR(64)   NOT NULL,
    file_type        VARCHAR(32)   NOT NULL,                      -- blf / mcap
    file_name        VARCHAR(512)  NOT NULL,
    s3_path          VARCHAR(1024) NOT NULL,                      -- S3 完整路径
    file_size_bytes  BIGINT,
    time_start       TIMESTAMP,                                   -- 文件覆盖的时间范围起始
    time_end         TIMESTAMP,                                   -- 文件覆盖的时间范围结束
    modalities       TEXT[] DEFAULT '{}',                         -- 包含的模态: {can_signal, video, lidar, gps, ...}
    mcap_channels    JSONB DEFAULT '{}',                          -- MCAP 专有：通道列表及其 schema
    checksum_md5     VARCHAR(64),
    status           VARCHAR(32)   NOT NULL DEFAULT 'uploaded',   -- uploaded / parsing / parsed / processing / processed / failed
    created_at       TIMESTAMP     NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE data_files IS '每个上传到 S3 的原始数据文件（BLF / MCAP）';
```

### 4. DBC 文件注册表

```sql
CREATE TABLE dbc_catalogs (
    dbc_id           VARCHAR(64)   PRIMARY KEY,
    dbc_version      VARCHAR(64)   NOT NULL UNIQUE,
    file_name        VARCHAR(256)  NOT NULL,
    s3_path          VARCHAR(1024),                                -- DBC 文件存放路径
    vehicle_model    VARCHAR(128),
    bus_count        INTEGER,
    signal_count     INTEGER,
    description      TEXT,
    is_active        BOOLEAN       DEFAULT TRUE,
    created_at       TIMESTAMP     NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE dbc_catalogs IS 'DBC 文件版本管理，一个 DBC 版本描述一类车型的 CAN 信号定义';
```

### 5. CAN 信号字典（DBC 解析结果的元数据）

```sql
CREATE TABLE can_signal_dict (
    signal_id        SERIAL        PRIMARY KEY,
    dbc_version      VARCHAR(64)   NOT NULL,
    can_bus          VARCHAR(32)   NOT NULL,                      -- 如 CAN1, CAN2
    can_id_hex       VARCHAR(8)    NOT NULL,                      -- 如 0x18F00530
    signal_name      VARCHAR(256)  NOT NULL,                      -- 车速、方向盘角度等
    start_bit        INTEGER       NOT NULL,
    bit_length       INTEGER       NOT NULL,
    scale_factor     NUMERIC(15,6) DEFAULT 1,
    offset_value     NUMERIC(15,6) DEFAULT 0,
    unit             VARCHAR(64),
    min_value        NUMERIC(18,6),
    max_value        NUMERIC(18,6),
    UNIQUE (dbc_version, can_bus, can_id_hex, signal_name)
);

COMMENT ON TABLE can_signal_dict IS '从 DBC 文件解析出的 CAN 信号字典——定义每个信号的物理含义';
```

### 6. 统一数据切片 ⬅️ 核心表

```sql
CREATE TABLE data_slices (
    slice_id         VARCHAR(64)   PRIMARY KEY,
    session_id       VARCHAR(64)   NOT NULL REFERENCES collection_sessions(session_id),
    task_id          VARCHAR(64)   NOT NULL,
    vehicle_id       VARCHAR(64)   NOT NULL,

    -- 时间窗口
    time_start       TIMESTAMP     NOT NULL,
    time_end         TIMESTAMP     NOT NULL,
    duration_ms      INTEGER       NOT NULL,                      -- 切片持续时长（毫秒）

    -- 切片类型
    slice_type       VARCHAR(32)   NOT NULL,                      -- time_window / scenario / event_trigger

    -- 场景标签（type = scenario / event_trigger 时填写）
    scenario_type    VARCHAR(64),                                 -- 如：高速巡航、城市拥堵、自动泊车、急刹车
    scenario_tags    TEXT[] DEFAULT '{}',                         -- 如：{night, rainy, curve}

    -- 包含的模态
    has_can          BOOLEAN       DEFAULT FALSE,
    has_video        BOOLEAN       DEFAULT FALSE,
    has_lidar        BOOLEAN       DEFAULT FALSE,
    has_gps          BOOLEAN       DEFAULT FALSE,

    -- 各模态在 S3 的具体路径
    s3_can_path      VARCHAR(1024),
    s3_video_path    VARCHAR(1024),
    s3_lidar_path    VARCHAR(1024),

    -- 各模态的时间对齐精度（毫秒）
    alignment_precision_ms INTEGER,

    -- 状态与统计
    status           VARCHAR(32)   NOT NULL DEFAULT 'created',    -- created / slicing / sliced / aligned / fused / ready
    frame_count_video INTEGER,
    frame_count_lidar INTEGER,
    can_signal_count  INTEGER,
    data_size_bytes   BIGINT,

    created_at       TIMESTAMP     NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMP     NOT NULL DEFAULT NOW()
);

-- 查询索引用到的枚举索引
CREATE INDEX idx_slices_session   ON data_slices (session_id);
CREATE INDEX idx_slices_vehicle   ON data_slices (vehicle_id, time_start);
CREATE INDEX idx_slices_time      ON data_slices (time_start, time_end);
CREATE INDEX idx_slices_scenario  ON data_slices (scenario_type) WHERE scenario_type IS NOT NULL;
CREATE INDEX idx_slices_modality  ON data_slices (has_can, has_video, has_lidar);

COMMENT ON TABLE data_slices IS '统一时间/场景切片——多模态融合分析的聚合单元';
```

### 7. MCAP 帧采样清单

```sql
CREATE TABLE mcap_sampled_frames (
    frame_id         VARCHAR(64)   PRIMARY KEY,
    slice_id         VARCHAR(64)   NOT NULL REFERENCES data_slices(slice_id),
    modality         VARCHAR(32)   NOT NULL,                      -- video / lidar
    frame_index      INTEGER       NOT NULL,
    timestamp        TIMESTAMP     NOT NULL,
    s3_path          VARCHAR(1024) NOT NULL,
    file_size_bytes  BIGINT,
    checksum_md5     VARCHAR(64),
    labels           JSONB         DEFAULT '{}',                  -- 标注平台回写的标签
    created_at       TIMESTAMP     NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_frames_slice    ON mcap_sampled_frames (slice_id);
CREATE INDEX idx_frames_unlabel  ON mcap_sampled_frames (slice_id) WHERE labels = '{}'::JSONB;

COMMENT ON TABLE mcap_sampled_frames IS '从 MCAP 中按采样策略提取的每一帧，发给标注平台的最小单元';
```

### 8. 数据处理作业日志

```sql
CREATE TABLE processing_jobs (
    job_id           VARCHAR(64)   PRIMARY KEY,
    job_type         VARCHAR(64)   NOT NULL,                      -- blf_parse / can_time_align / mcap_slice / mcap_sample / fusion_align
    target_type      VARCHAR(32)   NOT NULL,                      -- data_file / data_slice
    target_id        VARCHAR(64)   NOT NULL,                      -- file_id 或 slice_id
    status           VARCHAR(32)   NOT NULL DEFAULT 'queued',     -- queued / running / completed / failed
    input_config     JSONB         DEFAULT '{}',                  -- 加工参数（采样率、窗口大小等）
    output_summary   JSONB         DEFAULT '{}',                  -- 结果摘要（行数、帧数、耗时等）
    error_message    TEXT,
    started_at       TIMESTAMP,
    finished_at      TIMESTAMP,
    created_at       TIMESTAMP     NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_jobs_target ON processing_jobs (target_type, target_id);

COMMENT ON TABLE processing_jobs IS '记录每一次数据加工操作，用于追踪数据加工状态和故障排查';
```

## 三、数据加工状态流转

```
文件上传
  │
  ├─ [BLF] ──► queued ──► DBC解析 ──► StarRocks写入 ──► parsed
  │                                                        │
  │                                                        ▼
  │                                            时间对齐 / 场景切片
  │                                                        │
  ├─ [MCAP] ─► queued ──► 时间窗口切片 ──► 采样输出帧 ──► sliced
  │                                                        │
  └─────────────────────────────────────────────────────────▼
                                             统一融合切片 (data_slices)
                                                         │
                                                         ▼
                                                      fused
                                                         │
                                                         ▼
                                                 数据服务(已就绪)
```

StarRocks 中 CAN 解析数据表结构建议保持**一张宽表 + 信号名称展开**：

```sql
-- StarRocks 中的 CAN 解析数据表（示意）
CREATE TABLE can_signals (
    vehicle_id       VARCHAR(64),
    session_id       VARCHAR(64),
    blf_file_id      VARCHAR(64),
    signal_timestamp TIMESTAMP,                        -- 毫秒级精度
    can_bus          VARCHAR(32),
    can_id_hex      VARCHAR(8),
    signal_name      VARCHAR(256),
    signal_value     DOUBLE,                           -- 已应用 scale_factor 和 offset 的物理值
    quality_flag     TINYINT DEFAULT 0                 -- 0=正常 1=丢帧 2=校验错误 3=超范围
) DUPLICATE KEY (vehicle_id, signal_timestamp)
PARTITION BY RANGE (signal_timestamp) ();

COMMENT ON TABLE can_signals IS 'CAN 解析后的物理信号值，按时间戳分区存储';
```

## 四、多模态融合的关键：统一时间基准

所有时间戳在元数据表中统一使用 UTC 毫秒级 TIMESTAMP，以数据切片 `data_slices` 为**最小融合单元**。

典型的融合查询路径：

1. 业务方给出条件：`车辆 VIN-xxx` + `时间段 14:00-14:05` + `场景=高速巡航`
2. 查 `data_slices` → 找到匹配的切片 `slice_id`
3. 查 `mcap_sampled_frames` → 获取该切片下所有视频/点云帧及其时间戳
4. 查 StarRocks `can_signals` → 获取该时间窗口内所有 CAN 信号值
5. 在消费端按时间戳对齐——因为各模态已在切片内，时间误差在切片定义的窗口内可控

## 五、下一步建议

| 优先级 | 事项 | 说明 |
|--------|------|------|
| P0 | 先把 `collection_tasks` + `collection_sessions` + `data_files` 三张表建起来 | 覆盖"采集到上传"的链路，能知道 S3 里有什么 |
| P0 | S3 目录按 `{vehicle_id}/{date}/{task_id}/{file_type}/` 落盘 | 统一目录规范后，后续加工流程才能自动化 |
| P1 | 建 `data_slices` 表 | 这是多模态融合的核心锚点 |
| P1 | 写一个 BLF 上传后的自动解析 Hook | 文件上传完成 → 写入 data_files → 触发 DBC 解析任务 → 结果写入 StarRocks |
| P2 | 建 `mcap_sampled_frames` 表 + 对接标注平台 | 打通"MCAP→采样→标注"这条链路 |
| P2 | 建 `processing_jobs` 表 | 可观测性是后续排查问题的前提 |
